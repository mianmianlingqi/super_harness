# /sh-reflect — Super Harness 会话反思

执行完整的会话结束反思和知识蒸馏。

## 执行流程

### Step 1: 回顾完成的工作

列出本次会话实际完成的事项：
- 哪些做完了？
- 哪些没做完？
- 遇到了什么阻碍？

### Step 2: 自我评估

| 维度 | 评价 |
|------|------|
| 代码质量 | 好 / 中 / 差 — 为什么？ |
| 效率 | 好 / 中 / 差 — 哪里可以更快？ |
| 决策质量 | 好 / 中 / 差 — 有没有后悔的决定？ |
| 遵循协议 | 好 / 中 / 差 — 有没有跳过该做的步骤？ |

### Step 3: 提取经验

**什么做得好，值得重复？**
1. ...
2. ...

**什么可以更好？**
1. ...
2. ...

**学到了什么新东西？**
1. ...
2. ...

### Step 4: 蒸馏到 MEMORY.md

将可复用的经验写入 MEMORY.md：

- 新的坑点 → **Critical Gotchas**
- 新的架构决策 → **ADR 格式**
- 新的编码模式 → **Coding Conventions**
- 模块状态变化 → **模块状态表**

### Step 5: 写入日志

将经验记录到 `memory/YYYY-MM-DD.md`。

### Step 6: 计划归档

如果本次会话执行了计划：
- 将完成的计划从 `plans/active/` 移到 `plans/done/`
- 在计划文件中补完「执行日志」部分

---

**原则**：反思不是为了自责，而是为了下一次更好。重点是「下次遇到类似情况会怎么做」。
